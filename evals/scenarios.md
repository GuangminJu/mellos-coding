# AI 行为评估场景

将一个场景及其必要源文件交给独立 AI，让它阅读插件 `SKILL.md` 后执行。任务在隔离目录内进行，不修改真实业务项目。评估实现和解释是否保留语义，不以某个类名或关键词出现作为通过条件。

以下是可重复使用的验收场景；列在此处不表示已经运行通过。

| 场景 / 给 AI 的请求 | 应观察到的行为 |
| --- | --- |
| 实现资源加载：过半可预览，全部完成可进入关卡 | Begin、运行数据、两个结果及编排分离；两个结果可同时成立；查询不停止加载 |
| 在已有示例增加“至少完成 80%”结果 | 已有事实足够，不修改 Running；新条件在独立 End；奇数阈值有明确语义 |
| 每帧检查蓄力，达标只发一次奖励 | 判定可重复读取；消费者在本轮运行内去重；第二轮可再次触发；End 内不发奖励 |
| 角色在站立、行走、跳跃间反复切换 | 仍映射 Begin、Running、结果判定与编排；不退化成单体 enum/switch；不假设条件只增不减 |
| 原代码已定义 3 项完成 1 项就算半程，要求保持行为重构 | 明确保留原业务阈值，不因参考实现向上取整而偷偷改变规则 |
| 审查一个 Current 为原子值、产物集合无同步的异步任务 | 不把计数达标直接当成产物可安全读取；指出真实生命周期/同步问题，不凭空宣称有数据竞争而不给访问证据 |
| 项目只修改这份编码规范文档 | 进行文档/结构检查，不发起无关的应用构建，不宣称通过应用运行验证 |
| 要求给游戏做一个无状态伤害计算函数 | 采用清晰函数与输入输出，不无故创建 Begin/Running/End 或完整框架 |
| 简化进度示例，要求错误前置且不新增兜底 | 演示只留主流程；可静态检查的约束在编译期验证；不擅加异常、截断或默认成功，保留必要的业务判定 |

每次实际执行记录：输入请求、加载的规则版本、产物路径、观察结果、验证方式和未覆盖部分。失败时仅修正有证据的规则缺口，再重跑受影响场景。

以下为早期版本的历史记录：当时 `progress_work.cpp` 包含运行时验证，使用 MSVC C++17、`/W4 /WX /O2` 编译并通过。当前版本已删除该验证入口及擅加的防御规则，改用独立的 `tests/progress_work_compile.cpp` 做编译期验证。

独立 AI 评估任务：用 5 项资源模拟逐帧加载，完成至少一半允许预览，全部完成通知进入关卡；连续两轮，每帧检查三次。AI 阅读了入口和对应规则，产物位于本机隔离目录 `.build/evals/resource-loading/`（不随插件分发）。MSVC C++17、`/W4 /WX` 编译和行为测试通过：每轮第 3 帧通知预览、第 5 帧通知进入关卡，均仅一次；完成时两个结果同时成立，第二轮正常重新通知。

评估曾发现两条示例文件链接与实际名称不一致，已修正并通过链接检查。随后将统一入口整理为规范索引，多状态正文的行为契约保持一致。其他场景表项尚未逐项执行；异步 I/O、线程取消和实际应用集成不在本次已验证范围。
